Tri-Fair v8.4: a testable hybrid, not a claimed winner

The previous Qwen/Bias-in-Bios pilot provides a trade-off: the selected v8.3 prompt has lower inference cost and unfairness, while the selected NSGA-II prompt has higher accuracy and macro-F1. The two audited v8.3 candidates have search HV 0.768186 and search R2 0.113847. NSGA-II has search HV 0.770231 and search R2 0.114109. These small differences describe one seed and a two-candidate shortlist, not a statistically established advantage. No held-out noisy R2 can be computed from the supplied search-only report.

Hybrid method

Tri-Fair-v8.4-Hybrid subclasses the existing NSGA-II baseline. It retains the same initialization, full search-set evaluation, nondominated sorting, crowding-distance environmental selection and tournaments. A deterministic repeating portfolio alternates: (1) the existing crossover and objective-aware mutation, (2) compression of a high-quality parent or exact removal of its demonstration, (3) search-error-guided reflective revision. Every accepted candidate is measured; a generated hypothesis is never a measured result. Generation context and call limits are bounded and checkpointed. The baseline optimizer files and statistical metrics for the original three datasets are unchanged.

This is a separate experimental method and must be compared against both v8.3 and NSGA-II. It cannot guarantee dominance: quality, inference cost and fairness can conflict. Run ablations before crediting any component.

WinoBias adapter

Source: official WinoBias data, pinned commit. The packaged JSON contains the eight source files and occupation vocabulary with SHA-256 checksums, enabling offline preparation. It contains no Markdown or text files.

Two-choice adaptation: remove all bracket annotations; identify the first two occupation mentions, present them as options a/b with a reproducible paired permutation, and ask for the indicated pronoun's referent. The gold antecedent comes only from official annotations. Extra occupation mentions remain distractors in the sentence. This evaluates accuracy, not the original CoNLL coreference F1.

Adjacent source sentences, both task types and pro/anti gender variants form eight-row template families. Gender-neutral duplicate templates are connected before partitioning, including across official splits. One eight-row development family overlapping test is excluded, leaving 1,576 development rows and 1,584 official test rows. The protocol samples 640 development rows, a disjoint 160-row demonstration pool, and 800 test rows as complete families. Development is divided into outcome-independent search/validation blocks. This is a subset protocol, not the complete official benchmark.

Quality: accuracy. Unfairness: RMS of the type-1/type-2 pro-versus-anti accuracy gaps, with explicit accuracy/label-recall collapse guards applied to every method. Raw gaps, paired consistency, cell support and Wilson widths are reported separately. Support gates require both types and both conditions. Gender stereotypes in occupations are the scope; this does not establish fairness across all protected attributes.

Reproduce the first pilot

python -m tri_fair.cli.prepare --datasets winobias --seeds 72,73,74 --manifest-dir data/splits_v8_clean
mkdir -p logs
PILOT_METHODS="Tri-Fair-v8.4-Hybrid,Tri-Fair-v8.3,NSGAII-PO-Fair" \
PILOT_BUDGET=1000000 MODEL=qwen-3-30b SEED=72 \
sbatch --export=ALL --array=2-3%2 jobs/pilot_v84.sbatch

Array indices are 0=BBQ, 1=Civil Comments, 2=Bias-in-Bios, 3=WinoBias. Each method receives the same 1M downstream-token ceiling, shared choice grammar, two initial prompts, one maximum demonstration, and 35% final audit reserve. Generator tokens are separately recorded. Inference cost is a configured input/output-token score, not GPU monetary charges. Results use a fresh results/tri_fair_v84_pilot_1000000 namespace. Existing runs are preserved. Run all four tasks with --array=0-3%2 after the first two pass.

MO-CAPO-style presentation

Measured pilot table; vector objective-tradeoff figure. The generated LaTeX table is next to these files. These artifacts summarize v8.3 measurements, not unmeasured v8.4 performance.

Final results should include per-dataset quality/cost/fairness, optimistic and pessimistic held-out HV, approximation gap, noisy R2, and measured optimization expenditure. Use independent seeds and common token checkpoints. Select representatives on validation and freeze them before test; never combine the best quality, lowest cost and lowest unfairness from different prompts into one result row.

MO-CAPO's nR2 implementation selects using training/noisy objectives and evaluates the same candidate under held-out/true objectives. Here it is extended to three objectives with 4,096 shared Dirichlet preference vectors, seed 2026, fixed dataset cost bounds and HV reference (1.1,1.1,1.1). This is a three-objective adaptation, not a numerical reproduction of their two-objective indicator. Existing metric implementation is reused.

python -m tri_fair.reporting.pilot_indicators --report /path/to/pilot_report.json --output-dir results/pilot_tables
python -m tri_fair.reporting.front_report --evaluations /path/to/evaluated_validation.parquet --split validation --budget 1000000 --output-dir results/validation_fronts

The second command requires the per-prompt evaluation parquet files produced by the evaluation CLI, with aligned search and held-out metrics. It computes search-selected held-out noisy R2 and held-out optimistic/pessimistic HV. For test, use --split test only after freezing the final experiment configuration. Single-seed variation is not estimated. Statistical significance is not inferred by either command.

Evidence and limits

CPU integration tests verify real dataset preparation, split isolation, fairness collapse detection, hybrid full evaluation, checkpoint configuration, accounting and indicator mathematics using deterministic fake models. There is no GPU/model-quality validation of v8.4 in this package. The previous v8.3 GPU logs establish progress for that version only.
