The first command prints the plan and submits nothing. The second creates a fresh batch and prints training, validation and report job IDs. Training must finish before validation begins; validation must finish before aggregation. Consequently their concurrency limits do not add together. A failed dependency cancels its dependent job instead of leaving it pending indefinitely.

Do not install packages, edit source/job/plot files or pull further code changes while this batch runs. Source/job/plot fingerprints, package versions and existing split hashes are checked against matrix_config.json. A mismatch stops the job. Existing optimizer repeatability checks and fairness-readiness gates remain mandatory; they are not suppressed by this patch.

Results and figures

The exact batch root is printed at submission and saved with submission_jobs.json. Its default prefix is results/tri_fair_v88_three_seed_2000000/batch_.... Training checkpoints remain under qwen-3-30b/DATASET/seedSEED/TIMESTAMP/METHOD/run/. Validation membership Parquets are under heldout_validation/qwen-3-30b/DATASET/seedSEED/eval_checkpoints_union.parquet.

Aggregated files are under aggregate_validation/qwen-3-30b/: front_indicators_per_seed.csv (60 runs), front_indicators_summary.csv (20 method/dataset groups), and aggregate_protocol.json. Legacy columns named balanced_test_* describe validation here: inspect the explicitly saved evaluation_split.

paper_figures/ contains PNG, PDF and editable SVG exports: one four-panel reference figure per dataset; quality–cost attainment and fixed-fairness slices; nR2/HVpes token-budget trajectories; final HVopt/HVpes/nR2 comparisons; and a separate four-dataset few-shot figure for each method. The requested labels are Token Budget [×10⁶] and Avg. Cost [$] per 1M Calls.

CSV sources alongside the figures: measured_final_indicators.csv, measured_historical_trajectories.csv, fewshot_measured_points.csv, and attainment_support.csv. plot_protocol.json records input checksums and visual/metric conventions. Few-shot colour is measured output/(input+output) tokens on a fixed viridis 0–1 scale; it is not unfairness or cost share. Numbers show actual demonstration counts. Crowded labels are displaced with leader lines to the original points.

Cost means the configured token-price estimate per million calls, not actual cluster charges. For Qwen the existing weights are $0.11/M input tokens and $0.41/M output tokens; multiplying mean per-call token counts by those rates gives the plotted estimate per million calls. No pricing change or external current-price claim is made.

Top attainment panels use median and seed range. Historical trajectories use mean ± sample SD on common observed support, without extrapolation to unused budget. One seed has no shaded variability band. Final front indicators use the existing fixed bounds and 4096 seeded preferences. These descriptive intervals are not significance tests.

Retry postprocessing without retraining

export PILOT_RESULTS_ROOT="results/tri_fair_v88_three_seed_2000000/REPLACE_WITH_EXACT_BATCH"
STAGE=evaluate DRY_RUN=1 bash jobs/submit_three_seed_v88_postprocess.sh
STAGE=evaluate DRY_RUN=0 bash jobs/submit_three_seed_v88_postprocess.sh
# If validation already completed and only the CPU report failed:
STAGE=report DRY_RUN=0 bash jobs/submit_three_seed_v88_postprocess.sh

The evaluation retry requires all five completed training methods for each task and reuses compatible evaluation caches. It submits no training runs. If a training task failed, inspect its method logs first; this helper does not resume or silently replace failed optimization. The main submitter refuses an already existing batch directory.
