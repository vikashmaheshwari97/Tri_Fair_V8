Tri-Fair v8.8: probe before training

The recovered model loaded successfully on firefly1. It stopped at the same gate as pegasus2: Bios example dev|9162 received professor in one batch and comedian in the other order and alone. This failure occurs before optimizer search. Another GPU-only retry does not address the inference setting.

This repair makes the existing batch-invariance option explicit from process startup, forwards it through the pilot, checks that recorded CLI settings agree with the environment, and applies the same profile to training and held-out evaluation. No optimizer, fairness metric, baseline logic, or reported result is changed.

The probe runs the original mandatory gate twice on each of the four v8.8 initial prompts, including rendered demonstrations. It verifies the first prompt and eight search IDs against the old failed probe. A strict raw-output parser detects malformed labels instead of upstream's fallback to the first class. Every diagnostic call is charged against a separate 100K downstream-token cap, with at most 192 predictions. The model startup and kernel compilation still consume GPU time.

GPU execution has not been tested here. vLLM 0.24.0 documents batch invariance as beta. A finite probe pass does not prove universal determinism or better accuracy. There is no automatic fallback or automatic optimizer submission after the probe. A failure must remain a failure.

The default original-probe path is the exact failed run in batch batch_20261019T223036_12131. If it was moved, set ORIGINAL_PROBE to the actual original JSON before submitting. The job requests one H200 and can run on any Firefly node. There is no array and no B200 request.

The script prints the new proof path. Inspect the new job using its printed numeric job ID:

sacct -X -j REPLACE_WITH_PROBE_JOB_ID --format=JobID,State,Elapsed,ExitCode
cat REPLACE_WITH_PRINTED_PROOF_PATH
tail -n 100 logs/bios_stable88_REPLACE_WITH_PROBE_JOB_ID.err

Replace the placeholders; do not submit training unless Slurm says COMPLETED, exit code is 0:0, and proof says passed with eight scenarios, 192 predictions, and no disagreement. On failure, share the new proof, raw_outputs.json and job stderr. Do not repeatedly resubmit the same failed profile.

3. Only after a pass: five matched Bios methods

export PROBE_PROOF="REPLACE_WITH_PRINTED_PROOF_PATH"
MODE=train DRY_RUN=1 bash jobs/submit_bios_stability_v88.sh
MODE=train DRY_RUN=0 bash jobs/submit_bios_stability_v88.sh

This submits one training job, with the five methods sequentially, then a dependent validation and figure job. It requests one H200 per job. Validation cannot start if training fails; invalid dependencies are cancelled. Before training and evaluation, the helper checks source, launcher, packages, frozen manifest, model configuration and failure-evidence hashes against the passing proof.

Matched comparison: Tri-Fair-v8.8, NSGAII-PO-Fair, NSGAIII-PO-Fair, SPEA2-PO-Fair, RandomSearch-PO-Fair; Qwen; Bios; seed72; a 2M downstream cap per method. The new runtime profile applies to every method. Tri-Fair's own mandatory gate still runs inside its normal cap.

The four old Bios baseline measurements use a different inference profile, so the new Bios comparison retrains them. The other three datasets and all original results remain intact. The helper does not merge old-profile results into the new comparison. Existing results can still be inspected as historical evidence. Do not start seeds73/74 or a 5M matrix until this run has been reviewed.

New outputs: stable_profile.json, per-method pilot reports and checkpoints, ready_for_validation.json, held-out validation union, indicators including HV and nR2 where supported, and research figures. No significant performance advantage is established by one seed.
