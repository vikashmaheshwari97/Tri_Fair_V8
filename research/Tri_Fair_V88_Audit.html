Tri-Fair v8.8: repair the executed method before scaling the experiment

Audit of GitHub revision f99f64eb242ac907f2df9c72db39c7bdc4ec998e and Qwen seed-72 batch batch_20261019T203514_32425. Four datasets, five methods, a 2M downstream-token ceiling per optimizer run.

Verified fault: v8.7 attached demonstrations to Prompt objects but preserved a zero-shot template containing only <instruction>. Promptolution renders only placeholders present in the template. The demonstrations therefore did not reach the model. The stored demonstration list was not a reliable description of the executed prompt.

The baseline records contain no invisible demonstrations. The read-only audit script and machine-readable evidence are included in this bundle.

The duplicate attempts generally did not consume a full downstream candidate evaluation. The demonstrated harm is that these operators were ineffective: the available search space was narrower than intended. It would be incorrect to attribute all HPC usage or every quality loss to these attempts.

The cost branch also only normalized formatting and removed stored demonstrations; it had no LLM instruction-compression path for a zero-shot parent. The v8.7 formatter retained explicit label catalogues but appended a second generic output directive. The small live population and common quality cutoff limited parent diversity. These are separate implementation and design issues; their performance contributions have not been isolated by a GPU ablation.

3. What the reference repositories contribute

FAPO/FAFO is currently a pipeline-aware evaluation, attribution and variant workflow orchestrated by a coding agent. Its action space can include skills, parameters and graph structure. We adapt measured edit feedback and scoped task-preserving revisions; we do not claim a reproduction of its agentic system or import it as a drop-in optimizer.

MO-CAPO attaches demonstrations through correctly constructed Prompt objects and uses common-block challenger racing. Its original quality/cost setting does not make arithmetic averages of nonlinear group fairness valid. We retain full search coverage and direct pooled fairness computation rather than transplant that averaging.

The framework comparison repository provides benchmark wrappers and reproducible task/predictor/token-budget setup. Awesome-LLM-Prompt-Optimization is a literature catalogue, not executable evidence of a stronger method. Commit identifiers and exact inspected paths are recorded in v88_reference_review.json. No upstream source code is copied into this upgrade.

4. Experimental contract

Qwen; seeds 72, 73, 74; BBQ, Civil Comments, Bias-in-Bios and WinoBias; Tri-Fair v8.8, NSGA-II-PO-Fair, NSGA-III-PO-Fair, SPEA2-PO-Fair and RandomSearch-PO-Fair. The shared initial population is four, the demonstration limit is two, and the final audit shortlist is four. Both the initial 70% search allocation and reclaimed reserve stay inside each 2M downstream cap.

The 12 seed–dataset tasks each execute five methods sequentially, giving 60 optimizer runs and a 120M downstream-token ceiling. Proposal generation and held-out evaluation are additional measured usage. Equal ceilings do not imply identical actual tokens consumed. The default concurrency limit is five tasks, with one GPU per task; lower MAX_CONCURRENT if desired. Validation starts after all training tasks succeed, then the CPU report aggregates the complete matrix and generates figures.

Use a fresh tri_fair_v88_pilot_2000000 namespace. Do not relabel v8.7 checkpoints or delete unfavourable runs. No validation or test examples enter runtime optimization. Because validation results have already informed method development, reserve the untouched test split for the final frozen protocol.

5. What can and cannot be concluded

CPU tests establish implementation behaviour, not predictive improvement. No Qwen GPU experiment was run for v8.8 here. Repairing demonstrations can increase inference cost and reduce the number of fully evaluated candidates under the same token ceiling. Better accuracy, fairness, HV or nR2 must be measured. No guarantee of 18–19 first-place metrics is made.

In v8.7, Tri-Fair won six of 24 numerical dataset–metric cells but no front-indicator cells; nR2 was worst on all four datasets. That result identifies a selection/generalization weakness in addition to the verified rendering fault. A useful balanced operating point does not imply a superior Pareto front. The 24 cells also include correlated measurements—quality, fairness and hypervolume wins are not 24 independent statistical observations.

Three seeds improve the assessment of variability but are still a small sample. Report mean and sample SD, per-seed paired differences, actual token usage and Pareto trade-offs. Do not interpret descriptive wins or confidence bands as automatic significance. HVopt/HVpes refer to objective-front constructions, not confidence-interval endpoints.
