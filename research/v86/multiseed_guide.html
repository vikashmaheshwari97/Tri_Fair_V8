Tri-Fair v8.6: three-seed, four-dataset pilot

Apply this incremental patch after Tri_Fair_V86_Consolidated_Research_Upgrade.zip. Optimizers, splits and objective definitions are unchanged.

Qwen; seeds 72, 73, 74; BBQ, Civil Comments, Bias-in-Bios and WinoBias; Tri-Fair-v8.6 and NSGAII-PO-Fair. Twelve GPU training tasks each run both methods sequentially: 24 optimizer runs, each capped at 2M downstream optimization tokens, up to 48M total. The audit reserve is part of this ceiling. Meta-model and held-out evaluation work are additional; actual consumption may be lower. Five GPUs maximum for this submission, subject to scheduler availability. Existing jobs are unaffected.

unset SEED PILOT_METHODS PILOT_RESULTS_ROOT PILOT_STAMP NODELIST GPU_TYPE
export EVALUATION_SPLIT=validation
MODEL=qwen-3-30b PILOT_SEEDS=72,73,74 PILOT_BUDGET=2000000 MAX_CONCURRENT=5 DRY_RUN=1 bash jobs/submit_pilot_v86.sh
MODEL=qwen-3-30b PILOT_SEEDS=72,73,74 PILOT_BUDGET=2000000 MAX_CONCURRENT=5 DRY_RUN=0 bash jobs/submit_pilot_v86.sh

Expected array: 0-11%5. Indices 0–3 seed72, 4–7 seed73, 8–11 seed74. Within each block: BBQ, Civil Comments, Bias-in-Bios, WinoBias. The helper retains compatibility with a single SEED=72 invocation. Do not manually increase an old four-dataset array: it has no mapping for indices beyond 3.

Successful completion of all training tasks releases the twelve-task validation array. All validation tasks must complete before the CPU report job runs on the cluster default partition (no GPU requested). If a stage fails, downstream afterok jobs remain blocked; inspect the printed job IDs and logs instead of resubmitting the whole study.

Recommended optional preflight: create/validate all immutable manifests without regenerating existing splits:

python -m tri_fair.cli.prepare --datasets bbq,civil_comments,bias_in_bios,winobias --seeds 72,73,74 --manifest-dir data/splits_v8_clean

Outputs

The printed batch directory contains per-seed held-out results and figures under heldout_validation/qwen-3-30b/DATASET/seedSEED/. Across-seed results are under aggregate_validation/qwen-3-30b/:

  • front_indicators_per_seed.csv: all 24 run metrics, including balanced, quality-first, cost-first and fairness-first representatives.
  • front_indicators_summary.csv: mean and sample SD for all four datasets and both methods; quality, cost, unfairness, HVopt, HVpes and held-out noisy R2.
  • figures/: objective projections, front indicators, fairness-conditioned attainment, prompt composition, and logged optimization trajectories, each PNG and SVG. Trajectories require real history and never extrapolate outside common seed support.
  • aggregate_protocol.json: source checksums and exact study identities.

Aggregation refuses missing seed/dataset/method combinations. Three seed-specific runs provide descriptive variability, not an established significance result. Validation quality is accuracy except Bias-in-Bios, where the optimization quality metric is Macro-F1. The legacy CSV column prefix test_ inside held-out representative metrics describes the explicitly recorded validation split; it does not imply final test evaluation. No GPU performance or superiority claim is made by this patch.
