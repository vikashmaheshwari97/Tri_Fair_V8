Tri-Fair v8.5: research review and pilot protocol

Prepared 18 October 2026 UTC. Experimental implementation; no v8.5 GPU outcome is available. Supplied results remain unchanged.

Hybrid is retired from the new active workflow. Its source, registry entry and historical results remain available for reproduction and evaluation. Delete no existing result directories.

1. Why this upgrade

The seed-72 Qwen validation gives v8.3 the best Bios HV (0.742699) and noisy R2 (0.126890); NSGA-II leads WinoBias (HV 0.926034; noisy R2 0.079663). Hybrid does not dominate either control. Its balanced Bios unfairness rises from 0.154303 on search to 0.264520 on validation; WinoBias rises from 0.121659 to 0.230700. This suggests selection instability and insufficient retained alternatives, but one seed cannot identify a unique cause.

The prior pilot deliberately capped population size at two. That is a narrow debugging setting, not an implementation error. The new matched pilot increases it to four for every method. Increasing population and budget changes the protocol, so compare new methods within this new pilot rather than comparing only new v8.5 against old baseline scores.

3. Implemented changes

  1. Search-only stability-aware parents. For each eligible parent, re-score cached search predictions after leaving out one observed block. Parent quality is penalized by its largest quality deviation; parent unfairness is penalized by its largest fairness deviation. Folds with inadequate fairness support are omitted. The diagnostic has no extra model calls and is not a confidence interval.
  2. Preserve prompt components. Instruction revisions keep existing demonstrations. A demonstration proposal keeps the original instruction. Cost proposals can remove a single demonstration or shorten an instruction, and still require actual downstream evaluation.
  3. Evidence-preserving guidance. Bios retains valid professional training, BBQ checks passage determinacy and option mapping, Civil Comments distinguishes abuse from benign identity mentions, and WinoBias preserves the marked pronoun and grammatical evidence while avoiding occupation stereotypes.
  4. Measured paired feedback. WinoBias reflection can use previously observed pro/anti pair disagreements. Gold demonstrations come only from the frozen few-shot pool; no generated labels or search examples are added as demonstrations.
  5. Family-aware WinoBias bootstrap. Resample complete template families, not individual related sentences. This corrects the uncertainty sampling unit; raw fairness, quality and cost definitions are unchanged.
  6. Audited held-out membership. A new evaluation option uses the frozen full-search audit scores and total search-plus-audit tokens. It avoids selecting prompts with partial search scores after the audit. The older logged-front path remains available for historical evaluations.
  7. Dedicated matched submission. Four dataset tasks execute methods sequentially, then a validation array waits on successful training. Batch-specific result paths prevent accidental mixing of separate pilot attempts.

4. Auxiliary parent criterion

For observed search blocks B and candidate p:
  z(p,B) = measured pooled (quality, -cost, -unfairness)
  s_j = max_b |z_j(p,B without b) - z_j(p,B)| over valid folds
  parent_quality = quality - lambda * s_quality
  parent_unfairness = unfairness + lambda * s_unfairness
  lambda = 1.0; quality eligibility margin = 0.04

Use these values ONLY to select mutation parents.
Report, compare and compute HV/nR2 using the original measured objectives.
No fold is called independent validation or used as a significance test.

Default total ceiling is 12 method runs x 2M = 24M downstream optimization tokens, plus separately logged held-out inference. This is a ceiling, not a target to wastefully fill. Original strict admission and insufficient-evidence behavior remain intact.

6. Progression decision

First inspect all four dataset reports and held-out outputs. Check actual utilization, fairness support and the four-candidate trade-offs. If v8.5 improves a useful part of the frontier, repeat matched seeds 73 and 74. If it loses, retain the result and investigate the diagnostic rather than submitting a full 5M matrix merely to seek a favorable sample. Freeze the selected method and settings before final test evaluation. Compare additional unchanged methods before claiming superiority over them.

Suggested ablations: v8.5 with stability strength 0 versus 1, and demo search enabled versus disabled, under the same budget and seed list. The shared four-candidate protocol itself should be separated from algorithmic gains. No new statistical significance is inferred from this implementation.

7. Apply and run

Apply the incremental ZIP to the project that already has the held-out reporting fix. No dependency versions change. Run CPU tests and release verification, commit and push locally, then pull on Rocket. The submit helper is dry-run by default:

MODEL=qwen-3-30b SEED=72 PILOT_BUDGET=2000000 MAX_CONCURRENT=2 \
  DRY_RUN=1 bash jobs/submit_pilot_v85.sh

MODEL=qwen-3-30b SEED=72 PILOT_BUDGET=2000000 MAX_CONCURRENT=2 \
  DRY_RUN=0 bash jobs/submit_pilot_v85.sh

The helper submits training plus dependent validation, prints both job IDs and the exact batch results directory. Training logs are logs/pilot85_JOBID_TASK.out/.err; validation logs are logs/pilot85_eval_JOBID_TASK.out/.err. Dataset array indices are 0=BBQ, 1=Civil Comments, 2=Bios, 3=WinoBias.

For Mistral export MISTRAL_LOCAL_SNAPSHOT to the complete official-format snapshot first. For GPT-OSS, the helper excludes A100-80G and requests the existing large-memory H200/B200 pool; this is a resource choice, not proof of backend compatibility. Run the model smoke before submitting.
