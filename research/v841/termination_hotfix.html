Measured pilot assessment and termination correction

All six supplied processes completed with exit code zero. No all-three-objective dominance was measured. The hybrid improved the selected Bios quality and unfairness relative to v8.3 at essentially equal inference cost, but remained behind NSGA-II in quality. On WinoBias it reduced cost at a substantial quality/fairness penalty. v8.3 had the best search-shortlist HV and R2 on WinoBias; NSGA-II had the best indicators on Bios. These are one-seed search results, not significant held-out improvements.

Bios table / WinoBias table. CSV, LaTeX and JSON equivalents are included alongside each table.

Root cause

In both hybrid logs, the second compression proposal was rejected as not shorter. The inherited NSGA-II step passed an empty challenger list to its budget-fitting path and interpreted the empty result as an oversized candidate. It reported estimated=0, despite 263,534 search tokens remaining on Bios and 378,090 on WinoBias. This was a control-flow bug introduced by allowing rejected proposals in the hybrid, not GPU failure or an insufficient token ceiling. The baseline's normal nonempty candidate budget checks remain unchanged.

Correction

The hybrid now intercepts an empty proposal before budget fitting, keeps the existing population and counters, and advances to the next portfolio operator. Three consecutive empty proposals stop honestly as no_novel_candidates_after_three_rounds. Generation-call limits also keep their own stop reason. Actual oversized candidates still raise budget exhaustion with a positive estimate. No scoring, fairness, selection, data or baseline optimizer is modified.

The method identifier remains Tri-Fair-v8.4-Hybrid, but its recorded version is 8.4.1-nsgaii-full-evaluation-empty-proposal-safe. Old checkpoints are not compatible with this corrected control flow. The pilot always creates a fresh run, now under results/tri_fair_v841_pilot_1000000. Existing results are preserved; the uploaded measurements are not rewritten.
